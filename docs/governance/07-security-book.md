Status: P4 proposed implementation standards; P3 threat assessment preserved; effective controls and P12 hardening remain unverified.

## Purpose
Owns threat assessments, security control designs, authorization records and security test evidence.

## Inputs and planned scope
Assess untrusted spreadsheet/document content, paths, external processes, dependency supply chain, local access, log privacy and authorized website requests. Distinguish local jobs from network-dependent website work.

## Records and working rules
Record assets, threats, mitigations, linked requirements/risks/tests and residual risk approvals. Never store credentials or real client data in repository evidence. Define target ownership/permission, allowed hosts/actions, time/scope and approval evidence before live testing.

## Acceptance criteria
Trace controls to assessed threats; negative permission/input/path tests and privacy checks planned and later executed. Authentication mechanism and local storage controls remain design decisions, not P0 selections.

## Retry, recovery and resource safety
SEC-17 scope: any failure/retry/recovery; owner P/D/F/module lead; rationale: avoid repeated unsafe effects; verification: P3 error/fault matrix and actual bounded retry/cancel histories. Reconcile coding categories with DEV error tags, keep P3 codes stable. Error fields include stable error ID/code/category/severity, safe description/affected item, restricted diagnosticRef, job/version/attempt/correlation, timestamp, retry eligibility and recovery next action. Raw library errors must not cross the user boundary. Validation/input/permission/integrity/unsupported failures require correction; DB_BUSY/transient network only retry when operation semantics and current authorization permit. Lost external response is not proof no effect occurred.

Every eligible retry has explicit max attempts/elapsed time/delay/backoff (values selected per approved workload), idempotency key/effect record and cancellation checks; no infinite retry or automatic destructive replay. New immutable linked attempt retains failure evidence. Checkpoints/resume require verified profile-specific consistency, else retry from snapshots after diagnosis. Worker terminate only owned verified process tree, cancellation acknowledge is not stopped, partial output remains ineligible pending reconciliation/review. Recovered artifacts never silently inherit stale approval.

SEC-18 scope: resource-bearing tasks; owner F/D/resource lead; rationale: protect constrained laptop; verification: limits and P5/P12 resource tests. Bound CPU/memory/disk/file handles/processes/concurrent queue depth/temp lifetime; configurable budgets within approved maximums, preflight storage estimates and safe rejection/intervention for oversized tasks. Default future verification runs one heavy/browser suite at a time and one browser worker; this is a conservative execution setting, not a measured product capacity. Queue/concurrency numeric NFR budgets stay PROPOSED; progress and heartbeats cannot renew total deadline forever.

## Local diagnostics contract
SEC-19 scope: startup/scheduling/worker/progress/validation/review-approval/error/recovery/export/config events; owner COM-O; rationale: useful diagnosis without privacy loss; verification: schema/rotation/redaction/canary/export tests. Fields: eventId, timestampUtc, component/version, correlationId, eventType/severity, relevant job/version/attempt, safe code/disposition and evidenceRef, schemaVersion. Audit changes append with state transactions; debug diagnostics are not alternative approval truth. Never copy raw exception/request/credential or client content by default. Rotation/retention uses bounded file count/bytes/age under approved local settings; do not drop required durable audit to pass a budget. Full-disk logging failure surfaces and blocks unrecordable critical transitions, with safe local fallback marked unreconciled.

Diagnostic bundle: explicitly select current local logs/environment-safe inventory, redact and preview sensitive paths/URLs/screenshots/secrets, list exclusions/hash/schema and user consent, export locally. No automatic support upload. Redaction is a tested control, not perfect confidentiality proof. Local deletion/retention offers backup/export first; filesystem erase cannot guarantee removal from SSD remapping, journals, backups or prior copies. Separate physical backup destination needed for disk failure.
