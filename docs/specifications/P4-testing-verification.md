## Integrity, offline and recovery assurance
Future cross-module fault matrix interrupts every state/DB transaction/prepared-write/hash/rename/final-metadata/export/backup/migration boundary. Kill only owned worker/app in disposable test workspace; simulation doesn't prove real power-loss durability. Include forced termination, disk full, DB busy/corruption/write interruption, orphan leases/temp records, partial output, duplicate request/retry/lost external response, incompatible migrations, missing/tampered artifacts and stale approval. Expected: originals identical, incomplete state/evidence visible, no silent success/destructive duplicate, idempotent safe intents reconcile and package contains exactly approved current hashes. Restore verifies DB/schema/FKs/artifact inventory; corrupt backup blocks. Existing job/recovery/export/integrity tests plus TEST-0229–0232/0236/0239; retry profile must declare idempotency.

Offline test setup disconnects internet and blocks/observes outbound connections for app and child processes, with AI/Codex/auth/cloud/telemetry/subscription/backend absent. Exercise startup/create/config/DB/spreadsheet/doc/local-maintenance/history/templates/reports/export/backup/restore/diagnostics using installed supported profiles. Assert zero prohibited outbound attempts as well as successful local result, retain firewall/packet/process evidence and documented observation coverage. Authorized remote QA is a separate connected target test; local QA fixtures require explicit localhost exception, not permanent broad network permission. No hidden fallback or hosted asset/font/download. NFR-0005/0006/0021/0023 and existing TEST definitions remain NOT_RUN.

## Performance engineering and benchmark plan
Owner performance/QA lead; scope proposed NFR-0001/0002/0013/0024/WP-1. Stage A representative owner-dispositioned datasets -> B proposed numeric targets -> C measured baseline -> D observed bottleneck -> E correctness-preserving scoped optimization -> F regression benchmark. No invented measurement or automatic target approval.

Each benchmark profile records exact laptop/OS/CPU/arch/RAM/free local disk/storage/display/browser/toolchain/build/config/fixture sizes/counts, background load and warm/cold cache. Candidate repeat plan: one warmup plus five measured runs, median and p95/raw values, repeated under comparable environment; count/method remain proposed and adjusted with rationale. Compare same profile/baseline before/after changes; absolute approved NFR budget or owner-approved relative regression threshold defines failure (threshold pending measurements, no guessed clearance). Record variance, cancellation/timeout, unsupported/failed/skipped results and paired integrity evidence. Never optimize by disabling checks/durability/approval, dropping rows or exceeding grants.
